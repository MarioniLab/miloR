# 2.9.4 (2026-08-23)
+ **Bug fix:** `invertPseudoVar()` computed `Z * G` and `I + Z' W^-1 * (Z * G)` in two `omp parallel sections`. The second reads the product the first is still writing, so the block was a data race rather than a speed-up - the two steps are strictly sequential. Identical calls on identical data returned different estimates and took different numbers of iterations: across 20 repeats of one fit, 10 distinct variance component values and iteration counts from 22 to 48. They are now bitwise reproducible at a fixed 24 iterations. This was also the source of the apparent sensitivity to `glmm.control$init.u`, where the same data could return 0.12 or 557 depending on the random starting values, and of the fits that failed to converge within `max.iter`. Removing the block costs nothing - 0.148 against 0.151 seconds per iteration at n = 600.
+ **Behaviour change:** `fitGLMM()` and `testNhoods()` now estimate the negative binomial overdispersion as an additional variance component on the REML objective by default (`disp.as.vc=TRUE`), matching `testGeneticNhoods()`. The golden section search it replaces maximises the conditional NB likelihood at the current fitted means, which is circular: those means already contain the random effect BLUPs, so the random effects absorb the overdispersion before it is estimated. Across 50 simulated datasets with a true pool variance of 0.09 and a true size of 5, the median absolute error falls from 25.9% to 22.8% on the variance component and from 31.2% to 11.9% on the dispersion, and the median iteration count from 26 to 20; `lme4::glmer.nb` on the same data gives 26.7% and 12.5%. On the genetic path with the `sim_family` kinship, a true genetic variance of 0.25 and a true size of 5, the estimates move from 0.593 and the 1e4 Poisson-limit ceiling to 0.224 and 5.31. Set `disp.as.vc=FALSE` for the previous behaviour.
+ Under `disp.as.vc` the dispersion enters as sigma_0 with `dV*/dsigma_0 = I`, so it is estimated by the same Fisher scoring, the same step-halving at the boundary and the same convergence test as the other components, rather than off-line. `fitGLMM(Kin=)` and `fitGeneticNullGlmm()` agree to a median 7.1e-07 across 20 simulated genetic datasets.
+ **Bug fix:** the GLMM path of `testNhoods()` failed with `could not find function "bpstopOnError"` for anyone who had not separately attached `BiocParallel`, which is the normal case for `library(miloR)`. `glmmWrapper()` passed the stop-on-error setting through `BPOPTIONS`, and `bplapply` resolves that option from the calling frame rather than from its own namespace. The failure reproduces outside miloR with a fully qualified `BiocParallel::bplapply(..., BPOPTIONS=BiocParallel::bpoptions(...))` in a session where `BiocParallel` is not attached, so it is an upstream issue rather than a missing import - the package's NAMESPACE already imported `bpstopOnError`. The setting is now applied to the `BPPARAM` object instead, which avoids the path entirely and preserves the per-neighbourhood error capture that `bpok()` depends on. The package's own tests did not catch this because the test file attaches `BiocParallel` directly.
+ `testNhoods()` now rejects a mixed model design whose variance components cannot be identified, before fitting anything. A component is identifiable only if its design contributes something the fixed effects do not: `rank([X Z_j])` is always at least `rank(X)`, and equality means the levels of `Z_j` are fully determined by the fixed effect design. Rank deficiency in `X` itself is rejected on the same pass. Previously a design like `~Condition + (1|Condition)` surfaced downstream as a singular Hessian, which depended on the random starting values - the fit failed for 18 of 20 draws and returned a variance component of 1e-8 for the other two. With the dispersion estimated as a variance component the pseudo-variance is better conditioned and such a fit converges instead, leaving the degeneracy visible only as Satterthwaite degrees of freedom of order 1e-28 and p-values of exactly 1, which is easy to miss.
+ `disp.as.vc` is now supported by the Haseman-Elston solvers as well as by Fisher scoring, and `fitGeneticNullGlmm()` gains a `solver` argument so all three fitters offer the same choice. The overdispersion enters the Haseman-Elston regression as the identity basis, exactly as it enters the Fisher score with `dV*/dsigma_0 = I`.
+ The seven Haseman-Elston estimators and four vectorisers are replaced by a single `heSolveREML()` that works off a list of partial derivatives rather than off Z and a kinship matrix. The same code now serves `fitPLGlmm()`, `fitGeneticPLGlmm()` and `fitGeneticNullGlmm()`, which is what lets the overdispersion component be added in one place, and lets every solver be checked against an independent implementation of the same model.
+ The known `P W P` term of the Haseman-Elston moment is offset out of the response rather than carried as a freely estimated column, but only when W is actually known - that is, under `disp.as.vc`, where it is the Poisson part `1/mu` fixed by the current fitted means. Its coefficient is exactly 1, and freeing it costs both information and conditioning: the term correlates at 0.95 with the identity basis carrying `sigma_0`, taking the condition number of the design from 5.4 to 140 and losing half the fits their convergence. Under the golden section dispersion W carries a `phi` estimated on a different objective, is not known, and offsetting it pushed that error straight into the components - 3 of 15 fits converged and the variance component halved - so there the coefficient is still estimated freely.
+ Across 15 simulated datasets with a true pool variance of 0.09 and a true size of 5, `disp.as.vc` improves the dispersion for every solver: 6.15 to 5.00 under Fisher, 6.48 to 5.36 under HE and 6.48 to 5.13 under HE-NNLS. Every solver agrees with `fitGeneticNullGlmm()` on identical models to between 1.3e-06 and 3.1e-04. Fisher scoring remains the most reliable, converging 15/15 against 12/15 and 13/15 for the Haseman-Elston solvers.
+ The switch to HE-NNLS on a negative Fisher update is removed. Both solvers now guarantee strictly positive components - Fisher by step-halving along the ascent direction, Haseman-Elston by its own guard - so the branch was unreachable, and when it did fire it pinned the component at the boundary for every later iteration.
+ **Bug fix:** the ill-conditioned branch of `solveEquations()` warned that it was "trying pseudoinverse" and then called `arma::solve()` with `solve_opts::no_approx`, which *disables* Armadillo's solution for rank-deficient systems - strictly less tolerant than the `solve_opts::fast` used on the well-conditioned path. It threw `solve(): solution not found` and aborted the fit, so the branch that exists to survive a singular coefficient matrix was the one guaranteed to fail on it, and no pseudoinverse was ever computed. A variance component held at the constraint floor puts 1e8 on the corresponding diagonal of `G^-1`, which on its own is enough to trigger it: every Haseman-Elston fit on `data(sim_nbglmm)` aborted, as did all 4,500 attempted with an unrelated relatedness matrix. Both now return estimates.
+ `testNhoods()` rejects a design that asks for more random effect levels than there are observations. A relatedness matrix gives the genetic effect one level per observation, which is identified on its own because its covariance is `sigma_g * K` with `K` fixed - one variance parameter, not n - but a second random effect on top of it is not, since there is no residual left to distinguish it from. On the OneK1K data `~ ... + (1|pool_number)` with a kinship asked for 151 levels from 98 observations and returned a pool variance of 193, against 0.242 for the same random effect fitted without the kinship, reported as a converged fit for 499 of 500 neighbourhoods. It now fails in 1.8 s with a message naming the counts.
+ **Behaviour change:** `fitGLMM()` routes the kinship path through `fitGeneticNullGlmm()` rather than `fitGeneticPLGlmm()`. The latter appends `chol(K)` to `Z` as n dense columns, making the mixed model equations `(m+n) x (m+n)` and putting an O(n^3) term in every iteration; the former applies `K` once and never forms that block. Measured on identical data the two agree to 3.4e-06 on the variance component, 9.0e-07 on the standard errors, 1.7e-06 on the Satterthwaite degrees of freedom and 9.6e-07 on the p-values, with a median 5.3x speed-up end to end and 8.6-17x at the fitter itself - 178 s against 17.3 s per neighbourhood at n = 1000. The degrees of freedom are rebuilt from `V*(sigma)` directly: `function_jac()` is really evaluating `(X' V*^-1 X)^-1`, since the Schur complement of the mixed model equations is exactly the GLS variance-covariance, so the same jacobian is obtained without a coefficient matrix. `fitGeneticPLGlmm()` is unchanged and still available.
+ `testNhoods()` checks that a supplied relatedness matrix can actually separate the genetic variance from the negative binomial overdispersion, and refuses the fit when it cannot. Writing `K = I + E`, the two components enter the pseudo-variance as `sigma_g (I + E)` and `sigma_0 I`, so they differ only through the off-diagonal structure; when `E` is negligible the partial derivatives with respect to the two parameters are the same matrix and the REML information has two identical columns. The statistic is `||E||_F / ||K||_F`, the share of the matrix norm carried off the diagonal, which scales with cohort size for fixed per-pair relatedness - `||E||_F^2` grows as `n(n-1)` against a diagonal contributing only `n` - so one threshold serves any `n`: the OneK1K subset gives 0.05 at n = 98, and the same per-pair magnitude at n = 10,000 would give 0.45. Calibrated against simulation, where a ratio of 0.09 left 43% of neighbourhoods pinned at the variance floor with a median estimate a quarter of the truth, 0.25 left 29% pinned and the median 30% low, and 0.52 and above left under 10% pinned with the median within 11% of the truth. Fits are refused at or below 0.1 and warned between 0.1 and 0.35; `force=TRUE` downgrades the refusal to a warning. `data(sim_family)` scores 0.75 and passes.
+ The genetic variance component is fitted on `K = I + E`. With both `sigma_0 I` and `sigma_g K` in the pseudo-variance the two partial derivatives are `I` and `K`, which for a relatedness matrix of nominally unrelated individuals are numerically the same matrix - the REML information then has two identical columns and is exactly rank 1 when `K = I`. Writing `E = K - I` and collecting terms gives `V* = W + tau I + gamma E` with `tau = sigma_0 + sigma_g` and `gamma = sigma_g`. This is a linear change of basis with Jacobian `[[1,1],[0,1]]`, so the information transforms as `J' I J` and its rank is preserved: it creates no information, and when `E = 0` the fact that `dV*/dgamma = 0` states the problem plainly instead of leaving a ridge for the optimiser to wander along. On the OneK1K relatedness the correlation between the two bases falls from +0.999 to -0.017, the information is 4x better conditioned, and `V*` is 19.5x less sensitive to the ill-determined parameter. Verified behaviour-preserving: fits agree with the previous parameterisation to seven or eight significant figures on every seed tested, with identical iteration counts.
+ The feasible set for the variance components under the reparameterisation is `gamma > 0` and `tau > gamma`, since `sigma_0 = tau - gamma` must stay non-negative. That is a linear constraint on the pair rather than independent positivity, and the step-halving now enforces it; the Haseman-Elston solvers, which have no notion of it, have any infeasible pair lifted clear. `fitGeneticNullGlmm()` returns `Tau`, `Gamma`, `TauGammaMargin` and `TauGammaBinding` as a diagnostic - a binding margin means the genetic component has taken essentially all of the extra-Poisson variance, which is what a relatedness matrix without much relatedness in it produces.
+ `V*` is now assembled from the same partial derivative list the score and information are taken from, rather than rebuilt independently. Assembling it twice is how the genetic block came to hold `sigma_g L K L'` while its derivative stayed `K`.
+ Routing the kinship path through `fitGeneticNullGlmm()` fixes the long-standing failure of `data(sim_family)` to converge under the default settings. Through `fitGeneticPLGlmm()` all six solver and dispersion combinations ran to `max.iter` at 100, 500 and 2000 iterations; through `fitGeneticNullGlmm()` Fisher scoring with `disp.as.vc` converges in 34 iterations to a genetic variance of 0.2244, which a profile of the REML log-likelihood confirms is the maximum. The remaining combinations are diagnosed below.
+ The variance component update is relaxed against period-2 limit cycles. The PQL iteration alternates variance components -> fixed effects and BLUPs -> fitted means -> variance components, and on strongly overdispersed data that composite map can have a stable 2-cycle rather than a fixed point. On `data(sim_family)` - variance/mean 61.8, 12% zeros, simulated NB size 0.475 - the genetic component alternated between the constraint floor and 0.5403 with `|x_t - x_(t-2)| = 3.7e-15`, so nothing converged and no tolerance helped: two states were swapping rather than one settling. Sampling the fit at even iteration caps made the estimate look stable because it read the same phase each time. A relaxed update `sigma <- sigma + alpha (update - sigma)` collapses the cycle for `alpha < 1` and cannot move the answer, since at a fixed point the update equals the current value for every `alpha`; the feasible set is convex, so the `tau > gamma` constraint survives a convex combination too. `alpha` starts at 1 and halves only when a cycle is actually detected.
+ The cycle test is deliberately strict - the iterate must return to within a millionth of its position two steps ago while still moving appreciably. A loose threshold fires on ordinary damped oscillation: at 0.1 it slowed a healthy fit from 23 iterations to 61. A genuine limit cycle sits at a ratio of order 1e-15, leaving nine orders of margin.
+ Convergence is judged on the undamped step. Relaxation scales the step by `alpha`, so testing the relaxed increment would make the criterion `alpha` times easier to satisfy and stop the fit that much further from the fixed point - a weaker answer rather than a converged one.
+ Measured effect. On `data(sim_family)`, four of the five configurations that previously ran to `max.iter` now converge: HE in 37 iterations and HE-NNLS in 34 under `disp.as.vc`, and both in 38 under the golden section dispersion. Fisher scoring with `disp.as.vc` is untouched at 42 iterations and the same estimate. Fisher with the golden section dispersion still does not converge, because that cycle runs through `phi`, which is updated outside the relaxed block. Everywhere else the change is inert: across 6,000 fits spanning six levels of relatedness and both dispersion estimators, convergence counts are identical cell for cell (4,989 of 6,000 both with and without relaxation) and the variance components agree to the last digits.
# 2.9.3 (2026-08-21)
+ **Bug fix:** the REML score for the variance components in `fitPLGlmm()` and `fitGeneticPLGlmm()` mixed two bases. `sigmaScoreREML_arma()` took its trace term as `-0.5 tr(P dV_j)` in the REML projection basis but its quadratic form as `0.5 r' Vstar^-1 dV_j Vstar^-1 r` in the pseudo-variance basis. `Vstar^-1 - P` is positive semi-definite, so the quadratic form was inflated relative to the trace it is meant to balance and the resulting expression is not the derivative of any objective. On simulated data with a known pool variance of 0.09, the score at the first iteration was +2856 where the REML score is -35 - wrong in sign as well as magnitude - and `fitGLMM()` returned 31.1 rather than 0.09. The score is now taken entirely in the `P` basis, and the function no longer accepts a second basis to get wrong.
+ **Bug fix:** the model offset was left in the working response used for the mixed model equations and for the variance component estimation. The offset is part of the linear predictor but is not a column of `X`, so it is neither annihilated by `P` nor held fixed by the mixed model equations - the intercept absorbed it and then fed it back into the linear predictor on the next iteration, growing by `mean(offset)` per iteration without ever converging (intercept 669 after 101 iterations, against a true -3.9). The offset is now removed before the working response is used, as it already was in `fitGeneticNullGlmm()`.
+ **Bug fix:** the golden-section bracket for the dispersion was `[phi/2, phi]`, whose upper end is the current estimate, so the search could only ever return a smaller value. The dispersion halved on every iteration until the convergence check stopped it, regardless of the data - from a starting value of 4 it reached 0.0155 = 4 x 2^-8 on data with a true size of 5. The bracket is now two-sided, `[phi/2, 2 phi]`, capped at 1e4 as in `fitGeneticNullGlmm()`.
+ **Bug fix:** the dispersion update was skipped once two consecutive searches agreed to within 1e-2. That is a convergence test on the wrong quantity - the dispersion is estimated from the NB likelihood at the current fitted means, which are still moving by orders of magnitude in the early iterations - so two early searches agreeing switched the estimator off permanently. The variance components are estimated on the same pseudo-variance, so a pinned dispersion is absorbed into `W` and starves them. The search now runs while the model is still iterating, and its bracket tolerance is resolved relative to the bracket rather than at a flat 1e-2, which was coarse enough to prevent the outer fixed point from converging.
+ **Bug fix:** `nnlsSolve()` initialised the Lawson-Hanson passive and active sets on the wrong side of zero. A zero starting vector - which is what both the `HE-NNLS` solver and the negative-variance fallback supply - put every index in the passive set and left the active set empty, and an empty active set is itself a termination condition, so the routine returned the zero vector it was handed without doing any work. Every `HE-NNLS` fit reported variance components of exactly zero. The pivot search is now restricted to the active set, and the loops are bounded.
+ **Bug fix:** the residual column of the vectorised Haseman-Elston design was `vec(I)`. Under REML the moment being regressed is `E[P y* y*' P] = P W P + sum_j sigma_j P Z_j Z_j' P`, so that column must be `vec(P W P)`; `W = diag(1/phi + 1/mu_i)` is not a multiple of the identity, so the residual column could not absorb the working weights and the difference was taken out of the random effect instead, driving it negative. The ML variants use `vec(W)` for the same reason.
+ Negative variance component updates under Fisher scoring now retreat along the ascent direction by step-halving, as in `fitGeneticNullGlmm()`, rather than switching solver and clamping to the boundary, which pinned the component there for every later iteration.
+ On simulated data with a true pool variance of 0.09 and a true size of 5, `fitGLMM()` under Fisher scoring now returns a median 0.080 and 6.12 across 15 replicates, against 0.080 and 6.11 for `fitGeneticNullGlmm()` and 0.072 and 5.18 for `lme4::glmer.nb`. Previously it returned 31.1 and 0.0155. Converged fits agree with `fitGeneticNullGlmm()` to four or five decimal places.
+ **Bug fix:** the genetic random effect applied the relatedness matrix twice. `fitGLMM()` sets the genetic block of the design matrix to `t(chol(Kin))`, i.e. the Cholesky factor L, so that `Z_g Z_g' = L L' = K`. The corresponding block of G should then be `sigma_g I`, and the R-level `initialiseG()` builds it that way - but the C++ `initialiseG_G()`, which rebuilds G on every iteration, put `sigma_g Kin` there instead. The pseudo-variance therefore contained `sigma_g L K L'` while every partial derivative of V* with respect to `sigma_g` in the file - in `pseudovarPartial_G()`, `computePZList_G()`, `pseudovarPartial_VG()` and `vectoriseZGenetic()` - remained `K`. The score and the information were not derivatives of the model the pseudo-variance encoded, and the first iteration used a different parameterisation from every later one. On the `sim_family` IBD matrix at `sigma_g = 0.5` the two differ by 1.07 in absolute terms, 2.15x the largest element of the matrix they are meant to agree on. G and its inverse are now built in the whitened parameterisation, matching the design matrix and the derivatives; at a fixed state the pseudo-variance, REML score, information and variance component update now agree with `fitGeneticNullGlmm()` to 1e-6 or better, against a score of 81.6 versus 43.0 before. On `data(sim_family)` the genetic component drops from 19.04 to 1.29 and the dispersion from the 1e4 ceiling to 1.19, against a simulated size of 0.475.
+ Retire `initialiseG_G()`, `invGmat_G()`, `subMatG()` and `broadcastInverseMatrix()`. The whitened parameterisation makes G and its inverse diagonal, so the genetic path no longer inverts the relatedness matrix at all - one dense O(n^3) inverse per fit. That also removes the singular-kinship fallback, which inverted the leading N/2 x N/2 block and tiled it across all four quadrants of an N x N matrix; every column is duplicated, so its rank is at most N/2 and it cannot be the inverse of anything.
+ Fix a shadowed declaration in `fitGeneticPLGlmm()` that redeclared `VP_partial` inside the ML branch, so the `Vpartial` returned to R was empty for ML with Fisher scoring and `varCovar()` ran on an empty list.
+ Known limitation: the dispersion is still estimated from the conditional NB likelihood at the current fitted means, which biases it upwards by roughly 1.2x and occasionally drives the pseudo-likelihood iteration into a regime where it does not converge within `max.iter` (3 of 15 replicates above). `fitGLMM()` also draws its default starting BLUPs from `runif(0, 1)`, so results are not reproducible without setting `glmm.control$init.u`.

# 2.9.2 (2026-08-19)
+ **Behaviour change:** the negative binomial overdispersion in `fitGeneticNullGlmm()` and `testGeneticNhoods()` is now estimated as an additional variance component on the REML objective (`disp_as_vc=TRUE`, the default). Previously the dispersion was estimated by a golden-section search on the conditional NB likelihood evaluated at the current fitted means. That is circular, because those means already contain the random effect BLUPs: the random effects absorb the overdispersion before it is estimated, so the size parameter is driven to the Poisson limit (order 1e4 against a true value of 5 in simulation) and the random effect variances inflate to compensate (genetic component 0.372 against a true 0.1225). The legacy behaviour is incorrect and is retained only for reproducing earlier results - set `disp_as_vc=FALSE` to use it.
+ Fix `nbLogLik()`, which did not evaluate the negative binomial log-likelihood: it omitted `lgamma(y + r)`, used `r * (1 - mu/(mu + r))` in place of `r * log(r / (r + mu))`, and carried `lgamma(y + 1)` with the wrong sign. The first two terms depend on `r`, so `phiGoldenSearch()` was maximising the wrong function of the dispersion - it peaked at r = 0.785 against a true value of 5. This affects every GLMM fit, including `fitPLGlmm()` and `fitGeneticPLGlmm()`, since the working weights are `W = diag(1/phi + 1/mu)`. Together with the change above, null p-value calibration improves from lambda_GC = 0.26 to 1.02.
+ Introduce `testGeneticNhoods()` for genome-wide cell state QTL testing: the null model is fitted once per neighbourhood and every variant is scored against it, rather than refitting the full model per neighbourhood and variant. Use `testNhoods()` for designs with a single variable of interest such as age or disease status.
+ Introduce `refineGeneticHits()` to refit variants passing a screening threshold with the exact model, and `plotGeneticQQ()` for two-panel QQ plots with genomic inflation factors.
